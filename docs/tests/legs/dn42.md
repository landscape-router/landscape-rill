# dn42 接入验证（dn42-leg）

> boringtun 隧道、eBGP-lite、import/export policy 的验收场景。
> 设计规范：DN42_LEG（[../../design/legs/dn42.md](../../design/legs/dn42.md)）。
>
> e2e 形态（DN42_LEG §7，2026-09-03）：peer 容器 = **内核 WireGuard（wg-quick）+ FRR**（`e2e/mesh/dn42/`，
> 专用网段 192.168.243.0/24），一次拓扑同时验证 boringtun⇄内核 WG、eBGP-lite⇄FRR 两个互操作；
> node-a（lrill）无 coordinator 参与（dn42 leg 本地闭环，M1）。线格式 codec 单测 =
> golden vectors + 畸形语料（不 panic、错误只经 Result，对齐 REQ-059 风格）；
> v6 MP-BGP 全链路由 rill-dn42 进程内集成测试覆盖（e2e 与 FRR 的互操作覆盖 v4）。

## DNL-01 boringtun 隧道建立

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：node-a（boringtun）⇄ peer-r（内核 WG）握手收敛——peer-r `wg show` 出现 latest handshake；
  双栈隧道地址（tunnel /30 + /126）互通；peer 端点断开（`docker stop` peer-r）→
  恢复后握手自动重建

## DNL-02 eBGP 会话建立

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：TCP 179 会话 → OPEN（capability 协商：4B ASN、MP-BGP v4+v6、route refresh）→
  Established；peer-r `vtysh -c "show bgp summary"` 状态 Estab、node-a 侧会话状态日志一致；
  capability 不匹配（单元层模拟）→ NOTIFICATION Cease，不进 Established

## DNL-03 路由学习与注入

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：peer-r（FRR）公告 `172.20.100.0/24` → node-a LPM 表出现带 dn42 来源条目
  （含 AS_PATH/NEXT_HOP）；node-a tun0 侧 ping 目标可达（tun0 → 引擎命中 dn42 →
  boringtun 封装 → 隧道 → peer-r）。e2e 层覆盖 v4 互操作；v6 NLRI（MP_REACH）编解码
  与学习/撤销由 rill-dn42 进程内集成测试覆盖（session::tests，双 lrill 节点拓扑）

## DNL-04 路由宣告（export stub）

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：node-a 只 announce 配置的自家前缀（stub），peer-r FRR 表可见；peer 学到的路由
  （第三方前缀）不被重公告（transit 行为不存在）

## DNL-05 import policy

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：单元层——白名单外前缀拒、AS 环路（含自身 ASN）拒、bogon（保留空间）拒、
  max-prefix 超限触发 NOTIFICATION 关会话；e2e 层——peer-r 公告白名单外前缀
  （如 10.99.0.0/16）不出现在 node-a LPM、不可达；节点侧公告集合 = 配置驱动的聚合网段
  （172.20/14、fd00::/8），coord 白名单沿用 covered-by 语义（DN42_LEG §7 ③）

## DNL-06 撤销与收敛

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：peer-r WITHDRAW 前缀 → node-a LPM 同步移除 → tun0 侧不可达；重新公告 → 恢复
  （无状态残留；v1 单路径 best-path，无陈旧条目）

## DNL-07 会话故障

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：`docker stop peer-r` → 隧道断 → BGP 会话断（hold timer 或 TCP 断）→ 该 peer
  全部路由撤销 → 恢复 peer-r → 隧道 + 会话 + 路由自动重建 → ping 收敛（DNL-01~03 复归）
