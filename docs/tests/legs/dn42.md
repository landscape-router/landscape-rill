# dn42 接入验证（dn42-leg）

> boringtun 隧道、eBGP-lite、import/export policy 的验收场景。
> 设计规范：DN42_LEG（[../../design/legs/dn42.md](../../design/legs/dn42.md)）。
>
> e2e 形态（DN42_LEG §7，2026-09-03）：peer 容器 = **内核 WireGuard（wg-quick）+ FRR**（`e2e/mesh/dn42/`，
> 专用网段 192.168.243.0/24），一次拓扑同时验证 boringtun⇄内核 WG、eBGP-lite⇄FRR 两个互操作；
> node-a（lrill）无 coordinator 参与（dn42 leg 本地闭环，M1）；peer-r（FRR）+ peer-r2（**Bird**，
> profile late 门控，DNL-08~13）= 双 BGP 实现互操作：故障切换 / max-prefix / rogue 输入 /
> 表规模收敛与半表撤销。线格式 codec 单测 =
> golden vectors + 畸形语料（不 panic、错误只经 Result，对齐 REQ-059 风格）；
> v6 MP-BGP 全链路由 rill-dn42 进程内集成测试覆盖（e2e 与 FRR 的互操作覆盖 v4）。

## DNL-01 boringtun 隧道建立

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：node-a（boringtun）⇄ peer-r（内核 WG）握手收敛——peer-r `wg show` 出现 latest handshake；
  双栈隧道地址（tunnel /30 + /126）互通；peer 端点断开（`docker stop` peer-r）→
  恢复后握手自动重建

## DNL-02 eBGP 会话建立

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：TCP 179 会话 → OPEN（capability 协商：4B ASN、MP-BGP v4+v6、route refresh）→
  Established；peer-r `vtysh -c "show bgp summary"` 状态 Estab、node-a 侧会话状态日志一致；
  capability 不匹配（单元层模拟）→ NOTIFICATION Cease，不进 Established

## DNL-03 路由学习与注入

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：peer-r（FRR）公告 `172.20.100.0/24` → node-a LPM 表出现带 dn42 来源条目

  与学习/撤销由 rill-dn42 进程内集成测试覆盖（session::tests，双 lrill 节点拓扑）

## DNL-04 路由宣告（export stub）

## DNL-05 import policy

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：单元层——白名单外前缀拒、AS 环路（含自身 ASN）拒、bogon（保留空间）拒、
  max-prefix 超限触发 NOTIFICATION 关会话；e2e 层——peer-r 公告白名单外前缀
  （如 10.99.0.0/16）不出现在 node-a LPM、不可达；节点侧公告集合 = 配置驱动的聚合网段
  （172.20/14、fd00::/8），coord 白名单沿用 covered-by 语义（DN42_LEG §7 ③）

## DNL-06 撤销与收敛

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh

  （无状态残留；v1 单路径 best-path，无陈旧条目）

## DNL-07 会话故障

- 关联 REQ：REQ-015
- 测试层：集成 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/、rill-node/src/runtime/dn42.rs、e2e/mesh/dn42/、e2e/scenarios/dn42.sh
- 说明：`docker stop peer-r` → 隧道断 → BGP 会话断（hold timer 或 TCP 断）→ 该 peer
  全部路由撤销 → 恢复 peer-r → 隧道 + 会话 + 路由自动重建 → ping 收敛（DNL-01~03 复归）

## DNL-08 双 peer 故障切换

- 关联 REQ：REQ-015
- 测试层：e2e
- 状态：`已覆盖`
- 证据：e2e/mesh/dn42/、e2e/scenarios/dn42.sh、rill-dn42/src/rib/、rill-node/src/runtime/dn42.rs
- 说明：peer-r2（独立隧道 172.20.101.0/30、ASN 4242420003）同前缀双公告 → stop peer-r →
  hold 收敛后流量切换 peer-r2 → peer-r 恢复后回流（LocRib best-path 的真互操作验证）

## DNL-09 max-prefix 会话自保

- 关联 REQ：REQ-015
- 测试层：单元 + e2e
- 状态：`已覆盖`
- 证据：rill-dn42/src/policy/、rill-dn42/src/rib/、e2e/scenarios/dn42.sh
- 说明：peer-r2 max_prefixes=1 + 两条公告 → Cease(Max-Prefixes) 关停循环，peer-r 转发不受影响；
  借 node 重启改配置，同断言覆盖节点重启后隧道/会话/路由全量重建

## DNL-10 WG 层单点故障

- 关联 REQ：REQ-015
- 测试层：e2e
- 状态：`已覆盖`
- 证据：e2e/scenarios/dn42.sh、rill-dn42/src/tunnel/
- 说明：wg-quick down（容器不死）→ 隧道断 → hold 收敛 → SessionDown → peer-r2 顶上 →
  wg-quick up → 隧道/会话重建（隔离隧道层故障与进程生命周期）

## DNL-11 rogue BGP 输入 fail-closed

- 关联 REQ：REQ-015 / REQ-059
- 测试层：e2e
- 状态：`已覆盖`
- 证据：e2e/scenarios/dn42.sh、rill-dn42/src/wire/

  peer-r 转发不受影响（BGP socket 路径的对抗验证，SEC-08 同型）

## DNL-12/13 表规模收敛与半表撤销

- 关联 REQ：REQ-015
- 测试层：e2e
- 状态：`已覆盖`
- 证据：e2e/scenarios/dn42.sh、e2e/setup.sh、rill-core/src/route/mod.rs
- 说明：peer-r 公告 402 条 /24（dn42 真实表量级）→ FRR PfxSnt ≥400 且 node learned 全量收敛、
  规模表下转发不受影响；bgpd 换半表配置重启 → 撤销批量传播（PfxSnt ≤202）。
  **衍生修复**：PREFIX 掩码在非字节对齐长度（/14）上取反位错——matches/is_covered_by 修正为
  高位有效位掩码 + 地址族守卫（v4 bogon 不得"覆盖"v6 前缀），回归测试 rill-core route::tests
