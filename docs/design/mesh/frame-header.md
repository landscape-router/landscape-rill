## 1. 背景与设计目标

mesh 模式使用自研数据面：snow (Noise_XX) 握手派生会话密钥 + 自管 UDP socket。

帧头设计需要同时满足：

1. **快速转发**：中间节点（Linux 主机 / 中继）只读明文帧头即可转发，零加解密——转发路径不触碰载荷
2. **不信任中继**：中继节点无会话密钥、不可信；帧头**防外部篡改**——持 key_dst 者（中继/成员）可伪造帧头字节，但**伪造不出有效载荷**（AEAD + 握手层兜底，§3.2/§2.3），破坏性限于转发面（DoS 等价）
3. **XDP 友好**：固定布局、固定偏移、无动态解析，可直接在 eBPF 中处理

## 2. 帧格式

### 2.1 MeshFrameHeader（明文，固定 34 字节）

```
       0        1        2        3        4        5        6        7
     +--------+--------+--------+--------+--------+--------+--------+--------+
   0 |version |  type  | flags  |  ttl   |            to_node_id             |
     +--------+--------+--------+--------+--------+--------+--------+--------+
   8 |                     from_node_id                      |       seq       |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  16 |   len   |                     route_mac (前 6B)                       |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  24 |                       route_mac (续 8B)                               |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  32 |route_mac(续 2B)                                                       |
     +--------+--------+--------+--------+--------+--------+--------+--------+
```

| 字段 | 偏移 | 大小 | 说明 | 认证范围（ttl 置零后） |
|---|---|---|---|---|
| `version` | 0 | 1B | 协议版本；接收端校验，不匹配即丢弃 | route_mac + AAD |
| `type` | 1 | 1B | 包类型：单播 / 握手 / 心跳 / 控制（**预留**）/ 广播（0xFF，组播泛洪，§2.6——LAN 侧组播跨节点，broadcast_key 覆盖一对多） | route_mac + AAD |
| `flags` | 2 | 1B | 预留（压缩等） | route_mac + AAD |
| `ttl` | 3 | 1B | 跳数上限，逐跳递减 | **排除**（置零参与，见 §3.3） |
| `to_node_id` | 4 | 4B | 目标节点 ID（转发依据）；广播帧为保留值 `0xFFFFFFFF` | route_mac + AAD |
| `from_node_id` | 8 | 4B | 源节点 ID | route_mac + AAD |
| `seq` | 12 | 4B | 序号（目的端重放窗口） | route_mac + AAD |
| `len` | 16 | 2B | 载荷长度（含 AEAD tag），≤ 65535 | route_mac + AAD |
| `route_mac` | 18 | 16B | 双 siphash-2-4 并联截断，见 §3.1 | 自身不参与 |

固定总长 **34 字节**。所有多字节字段网络字节序（大端）。XDP 只需固定偏移，无需对齐。

`seq` 重放：接收端按 `(from_node_id, to_node_id)` 维护滑动窗口（默认 1024），回绕按模 2^32 滑动窗口处理（窗口远小于 2^31，回绕无歧义）。

### 2.2 载荷

```
载荷 = AEAD(ChaCha20-Poly1305) 加密数据 + 16B tag
```

- 密钥：由 Noise_XX 握手逐节点对派生（每对节点独立会话密钥）
- AAD：`MeshFrameHeader` 中除 `ttl`、`route_mac` 外的全部字节（即 ttl 置零后的 `帧头[0..18]`）
- nonce：`32-bit 会话盐（握手派生，每会话随机）|| 64-bit 方向计数器`；每对节点按方向独立计数，不重用；AAD 中已含 `from/to/seq`，与重放窗口语义一致
- **接收上限（REQ-053）**：合法帧上界 = MTU(1420) + v2 帧头(42) + tag(16)（握手帧更小）；接收方按此上界加余量分配缓冲，超长报文被截断后**显式丢弃并计数**（发送侧不得依赖超过该上界的单帧）

### 2.3 握手帧载荷语义（type=握手，防重定向）

帧头 `to_node_id` 不可信（§3.1：成员可改写并重算 route_mac，把 A→B 的握手重定向为 A→B'），握手必须双保险：

1. **msg1 载荷内携带目标 node_id**（显式声明"与谁握手"）；接收方校验：目标 ≠ 自己 → 拒绝（第一道防线，防重定向）
2. **握手完成后身份绑定交叉验证**：双方用 coordinator 签发的 `node_id ⇔ 静态公钥` 绑定验证对方（CONTROL_PLANE §3.1/§6）——防冒充（最终防线）

这是"成员可伪造帧头"场景下的核心防护，实现时 msg 内 node_id 的携带与校验必须严格实现与测试。

### 2.4 握手报文规格（type=握手，Noise_XX 载荷）

| 项 | 规格 |
|---|---|
| **prologue** | `network_id \|\| 帧头协议版本`——防跨网络/跨版本会话混淆（不同网络/版本的握手互不相认） |
| **msg1 载荷** | **目标 node_id（4B，载荷前缀，固定偏移）** + Noise_XX 第一条消息体——接收方校验目标 = 自己，否则拒绝（§2.3 第一道防线） |
| **msg2 载荷** | Noise_XX 第二条消息体（响应方临时公钥；**此阶段不做静态公钥验证**——XX 模式响应方静态公钥在 msg3 中才加密传递） |
| **msg3 载荷** | **发起方身份绑定（coordinator 签名，CONTROL_PLANE §3.1）+ 会话盐（4B）** + Noise_XX 第三条消息体——接收方验证绑定有效性；**发起方在 msg3 完成后用 netmap 绑定交叉验证响应方静态公钥**（§2.3 第二道防线，静态验证只发生在握手完成时，不发生在 msg2） |
| **会话盐** | 发起方生成 32-bit 随机盐，**随 msg3 载荷携带**；接收方在 msg3 后获得完整 nonce 域（`盐 \|\| 64-bit 方向计数器`，§2.2） |
| **方向计数器初值** | 每对节点按方向独立，从 0 起；AAD 含 from/to/seq 与重放窗口语义一致 |
| **rekey 双密钥窗口交叠** | Noise rekey 后新密钥立即生效；**旧密钥保留 5s 残留期**——期间新旧两套重放窗口并存（旧窗口按旧计数继续滑动，新窗口从 0 起），残留期过后旧窗口销毁；在途/乱序旧包在残留期内可解，过期丢弃 |

- 握手帧**不经转发路径认证**（载荷为 Noise 消息，无 AEAD——转发节点只需按 `to_node_id` 转发，与普通帧同路径）
- **握手帧的重放防护归属 Noise 状态机**（握手消息一次性、Noise nonce 单调递增），**不依赖 seq 重放窗口**——seq 窗口仅用于已建会话的数据/心跳帧
- 实现时以上规格为**强制要求**（msg1 目标校验 + msg3 绑定验证 + rekey 窗口交叠语义需专项测试，见 [tests/security/frame-attacks.md](../../tests/security/frame-attacks.md)）

### 2.5 心跳帧规格（type=心跳）

- **适用范围**：仅**已建立会话的节点对之间**（数据面活性探测，CONNECTIVITY §6）
- **载荷**：AEAD 加密（逐对会话密钥）+ 空载荷（仅帧头 + 16B tag）——与数据帧同认证强度
- **防重放**：`seq` 走既有重放窗口（§2.1）
- **未建立会话时的活性检测**：走 probe 机制（CONNECTIVITY §4），**不混用心跳帧**（probe 无认证为有意设计，仅验证可达性）

### 2.6 广播帧规格（type=广播，组播泛洪）

> v1 曾砍掉广播（决策记录 2026-08-15），理由是"逐对会话密钥无法覆盖一对多"。**IPv6 ND 需求重新开放**：TUN 是 L3-only，内核在 land0 上自动应答自身地址的 NS/NA，但目标 IP 属 mesh 前缀时 NS（目的地址为 solicited-node 组播 `ff02::1:ffxx:xxxx`）必须跨节点送达拥有者——这是纯单播转发到不了的组播流量。**v1.1 实现决议：广播密钥方案复用 v1 砍广播时已预埋的三件套**（`type=广播`、`to=0xFFFFFFFF`、keydist 下发的 `broadcast_key`），以**泛洪**语义落地，不引入新协议字段。

- **触发**：LAN 侧（tun0）收到的**组播 IP 包**（IPv6 `ff00::/8` 组播——含 ND solicited-node、RS、mDNS；IPv4 `224.0.0.0/4` 组播）。v1 不含 IPv4 子网定向广播（`255.255.255.255`/子网广播地址）
- **帧头**：`type = 广播(0xFF)`、`to_node_id = 0xFFFFFFFF`、`from_node_id = 源节点`、`seq = 每源全局广播计数器`（与单播 seq 域分离——广播是"虚拟会话"，计数独立于任何节点对）
- **密钥与认证**：载荷 AEAD 与 route_mac **均用 `broadcast_key = KDF(主密钥, 0xFFFFFFFF)`**（keydist **按需下发**——仅能力位含 `broadcast`（0x20，CONTROL_PLANE §3.1）的节点持有，§6）；nonce = `0x00000000 || seq`（同 §2.2 会话 nonce 构造，salt 恒 0）；AAD = ttl 置零帧头
- **重放窗口**：接收端按 `(from_node_id)` 维护独立广播窗口（虚拟会话语义——每源一个 1024 窗口，与单播 `(from,to)` 窗口并存不干扰）
- **relay 泛洪语义**（§4 广播路径）：
  - 校验顺序：version → `type=广播` → broadcast_key 存在 → route_mac（bkey）→ **`(from_node_id, seq)` 去重**（30s TTL 的 seen 集，防环防风暴；与重放窗口并存——去重防转发环，窗口防端点重放）→ `ttl > 0` → 自交付 + `ttl-1` 泛洪
  - **自交付**：广播帧对每个节点都是接收者（`to` 是保留值≠自己），本节点也消费一份
  - **泛洪范围**：endpoint_table 中**除自己与源节点外、且能力位含 `broadcast`（0x20）的端点**（未 opt-in 端点不收到广播帧，发送侧过滤）；未记录能力位的端点按未 opt-in 处理（fail-closed）；不向源节点回泛（源端点已知）
  - **限速**：令牌桶（容量 64、补充 16/s），发送与转发共用出口桶——防成员用广播放大流量（§5 泛洪限速）
  - **无会话也可发**：广播帧不依赖逐对会话密钥 → 泛洪目标含**无会话（但 opt-in）端点**（不触发懒握手——避免组播风暴引发握手风暴）；接收方回程（NA/echo 等单播）走正常单播路径的懒握手
- **opt-in（v0.9）**：广播是**能力位 opt-in**（`broadcast`，0x20，CONTROL_PLANE §3.1）——未 opt-in 节点：keydist 不下发 broadcast_key（§3.1 无 key 即丢，fail-closed）、发送侧泛洪不发给它、本地 LAN 组播不泛洪（无 key 无法构建广播帧）；opt-in 判定数据源 = 注册能力位 → netmap 全量广播，无状态同步开销
- **ND 工作方式（零用户态 ND 逻辑）**：NS（组播）经泛洪到达拥有者 land0 → **内核 ND 自动应答 NA**（单播回程走 mesh 单播路径）→ 请求方内核完成邻居解析后发数据包（单播路径）。用户态不解析 ND，只做组播包的泛洪转发
- **源认证边界**：broadcast_key **opt-in 节点集合内共享 → 广播帧无源认证**。成员可伪造 `from_node_id` 注入伪广播（内容层可达），后果 = 误导邻居缓存/DoS 等价——**接受**（与帧头层成员能力同级，§5 成员能力矩阵）；非成员无 key 进不来
- **密钥轮换**：broadcast_key 随 keydist key_version 轮换（master 更换）；切换时清空广播重放窗口与去重集（新旧密钥帧不可互验，窗口重置无歧义）

### 2.7 v2 帧头规格（v2 路径数据面，REQ-034 实现落档）

```
       0        1        2        3        4        5        6        7
     +--------+--------+--------+--------+--------+--------+--------+--------+
   0 |version |  type  | flags  |  ttl   |            to_node_id             |
     +--------+--------+--------+--------+--------+--------+--------+--------+
   8 |                     from_node_id                      |       seq       |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  16 |   len   |                    path_id (8B，固定 18..26)                |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  24 |  path_id（续 2B）  |              route_mac (前 6B，26..42)           |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  32 |                       route_mac (续 8B)                               |
     +--------+--------+--------+--------+--------+--------+--------+--------+
  40 |route_mac(续 2B)                                                       |
     +--------+--------+--------+--------+--------+--------+--------+--------+
```

- **`version=0x02`、固定 42B**；`path_id`（8B，网络字节序）位于 18..26，`route_mac` 移至 26..42——v1 布局 18..34 不变
- **认证范围（ttl 置零后）**：v2 认证输入 = `帧头[0..18] || path_id`（26B），route_mac 与 AEAD AAD 共用（§2.2/§3.1 语义扩展）
- **密钥选择**：v2 route_mac 用 `key_path = KDF(主密钥, path_id, path_epoch)`（§3.11.5，按路径签发、只发路径参与者）；**`path_id=0` = 默认路径 = 现有 `key_dst` 语义**（v1 兼容回退）
- **互操作**：帧头版本即判定（v1 节点收 v2 帧 → version 不匹配丢弃，§2.1 既有语义）；发送方按对端 `protocol_version`（netmap 条目，≥2 = v2）决定帧头版本——v2 对 v1 对端恒发 34B v1 帧（path_id 隐含 0）
- **握手/心跳/广播帧恒为 v1 帧头**（key_dst/broadcast_key 路径）——路径是已建会话后的数据面概念
- **转发**：转发节点按 `path_id` 查 `key_path` 校验 route_mac（无授权 → 丢弃，fail-closed）；下一跳端点按路径 hops（本节点在路径中的后继）解析（§3.11 转发语义）

### 2.8 underlay 传输线格式（REQ-054 实现落档）

帧本体与传输解耦——**帧字节跨传输逐字节一致**，传输档只是外覆差异：

| 档 | 线格式 | 定位 |
|---|---|---|
| 裸 UDP（默认） | 报文 = 帧本体，无前缀 | 常态 |
| 真 TCP（兜底） | `2B BE 长度前缀 + 帧本体`，一条流上帧/probe 靠首字节分类共存 | UDP 被封禁网络的兜底（HOL 代价） |

- 传输档为**节点配置维度**（`data_transport: udp\|tcp`，v1 全网同档假设）；netmap 端点不带传输标注，端点地址即连接地址——v1 直连场景成立；**非 UDP 传输的公网端点发现（TCP NAT 映射）挂账未解**（UDP echo 学不到 TCP 洞，另立需求）
- §2.1 golden vectors 天然覆盖所有传输（帧本体不变）；传输层断言：UDP 报文逐字节 = 帧本体、TCP 线上 = 前缀 + 帧本体（专项测试钉死）

### 3.1 route_mac（轻量，转发节点校验）

```
route_mac = siphash_2-4(key_dst, 帧头[0..18] 且 ttl 置零) 的低 16 字节
其中 key_dst = KDF(coordinator 主密钥, to_node_id)
```

- **16B 输出**：由两个独立 128-bit siphash 密钥（`k1, k2 = KDF(key_dst, 0/1)`）并行计算，输出 `siphash(k1, ·) || siphash(k2, ·)` 各 8B 拼接。XDP 内联两次 siphash（约几十条指令），开销可忽略；离线恢复难度提升到 2^128 量级（8B 截断方案的 2^64 不再成立）
- **目的**：防帧头伪造与篡改（`ttl` 除外），保证转发依据可信
- **校验方**：转发节点（用户态 socket 或 XDP），一次双 siphash，几乎零开销
- **密钥（共享性质，安全边界所在）**：`key_dst` 由 coordinator 按目的节点派生；v1 全量互连下**每个成员实际持有全网 key_dst**（发送方计算 route_mac、转发节点校验都需持有）——route_mac 提供**完整性与防外部篡改**，**不提供源认证**：成员可为发往 B 的帧伪造任意 `from_node_id`（转发节点校验无法识别）。安全边界 = 防外部攻击者篡改/注入；**成员伪造源靠目的端 AEAD 兜底**（伪造者无 (A,B) 会话密钥，解密失败）+ 握手层身份绑定验证（§2.3）。泄露影响：`key_dst(B)` 泄露 = 可伪造发往 B 的帧头（仅头部，AEAD 兜底）；节点被攻破 = 其持有的全部 key_dst 泄露（即全网）。广播密钥 `KDF(主密钥, 0xFFFFFFFF)`（§2.6 已激活：广播帧 AEAD 与 route_mac 均用 broadcast_key，**共享范围 = opt-in 节点集合**，内部仍无源认证，边界见 §2.6）
- **不重签**：转发节点递减 `ttl` 不影响 route_mac 验证（校验时 ttl 按 0 参与，线路上 ttl 的任意值都被忽略），递减后**无需重新计算**
- **桥节点例外（联邦 v2 边界）**：桥节点是**唯一被授权重签 route_mac** 的节点类型——跨网络边界时用目标网络的 `key_dst` 重算一次后转发；其余转发节点仍不重签。AAD 排除 route_mac（§2.2），重签不破坏端到端 AEAD 认证（§3.2）。广播是否跨网透传由桥节点策略决定（默认不透传）

### 3.2 AEAD 全包认证（强，目的端校验）

- **目的**：端到端完整性 + 保密性。载荷密文与帧头（AAD）一起被 tag 覆盖
- **校验方**：目的节点（有会话密钥）；中间节点无法验证，也无需验证
- **效果**：即使 route_mac 被攻破（key_dst 泄露），任何帧头/载荷篡改仍会被目的端丢弃

### 3.3 ttl 为什么排除在认证外（做法 A）

`ttl` 是唯一逐跳递减字段，端到端认证与"可递减"冲突。参考 **IPsec AH（RFC 4302）**：认证计算中 TTL/hop limit 按 0 处理。

具体做法：route_mac 与 AEAD AAD 的计算输入均为 **ttl 置零后的帧头**，线路上 ttl 的任意取值不影响认证校验。排除后安全无害：

| 攻击者篡改 ttl | 后果 | 危害 |
|---|---|---|
| 改大 | 包可多走几跳 | 仅浪费带宽，最终节点仍递减到 0 |
| 改小 | 包提前被丢弃 | 仅影响该包，等价 DoS 一个包 |

**不能**转向（to_node_id 被认证）、不能注入、不能读取载荷。因此 ttl 单独裸奔是闭合的安全设计，且换来转发节点零重签开销。

## 4. 转发路径

```
收到 UDP 包
  → 读 MeshFrameHeader（固定偏移，无需解析）
  → route_mac 校验（ttl 按 0 参与；XDP 中用 BPF map 按 to_node_id 索引转发密钥）
  → 递减 ttl（仅改写 ttl 字节，其余帧头不动）
  → 查表: BPF map / 用户态表 (to_node_id → 当前 UDP 地址)
  → 改写外层 IP/UDP 目标地址（帧头、载荷原样不动）
  → 发送
```

- 载荷全程零加解密——转发节点不是隧道的对端
- 联邦跨界（v2）：桥节点在边界重签 route_mac（用目标网络 `key_dst`，§3.1 例外），其余转发路径照旧；端到端握手与会话不受影响
- 广播（L2 桥接）：**已激活（v0.7 泛洪，v0.9 opt-in，§2.6）**——`type=广播` 走独立的泛洪路径（去重/ttl/不向源回泛/令牌桶限速/仅 opt-in 端点），不适用本节的单播查表路径，语义见 §2.6；subnet router/手机场景仍为 L3 路由
- 实现两阶段：Phase 1-2 用户态 socket 转发（功能先行）；Phase 3 XDP 快速路径（性能）

## 5. 安全分析

| 攻击者能力 | 后果 | 防护 |
|---|---|---|
| 读取帧头 | 获知通信关系、流量大小、时序（元数据） | 所有 VPN 均泄露，可接受 |
| 篡改 `ttl` | 多走几跳 / 提前丢弃 | 无害（认证排除，§3.3） |
| 篡改其他帧头字段 | 转发被导向错误节点 | 转发节点 route_mac 校验失败，丢弃 |
| 伪造完整帧头（**非成员**） | 注入伪造流量 | 无 key_dst 无法生成合法 route_mac；转发节点校验失败丢弃 |
| 伪造完整帧头（**成员**，key_dst 全网可得） | 伪造任意 from_node_id / 重定向握手 | route_mac **不认证源**（§3.1）；载荷由目的端 AEAD 拦截（无会话密钥解密失败）；握手重定向由 msg1 目标 node_id + 身份绑定交叉验证拦截（§2.3） |
| 离线恢复转发密钥 | 伪造到特定目的帧头 | 16B 双 siphash，恢复难度 2^128；影响限于帧头伪造（与成员能力同级），AEAD 兜底 |
| 重放旧包 | 目的端收到重复数据 | `seq` 重放窗口（AAD 认证，不可改） |
| 读取 / 篡改载荷 | 窃听、注入 | ChaCha20-Poly1305 加密 + 认证 |
| 成员灌垃圾 AEAD 包 | 目的端解密失败开销（DoS） | 无共享密钥方案固有极限；接收端对未知会话帧限速（令牌桶） |

**信任模型**：不信任中继。中继可做的极限是丢弃包（转发 DoS），无法读取、篡改、注入有效数据。**成员**可伪造帧头（源认证缺失），载荷安全由 AEAD + 握手层身份验证兜底。

**成员能力边界（内部恶意）**：成员持有全网 key_dst（§3.1），帧头层可伪造/捣乱，但破坏性被限制在路由层：

| 层面 | 成员能力 |
|---|---|
| 内容层（载荷） | 读不到他人密文（逐对会话密钥）；伪造不了"伪装他人"的有效载荷（AEAD 解密失败） |
| 握手层 | 可中断（DoS），不可冒充/重定向（msg1 目标 node_id + 身份绑定，§2.3） |
| 路由层 | 可伪造帧头/from、丢包、灌垃圾包——全部等价转发面 DoS |

**设计哲学**：route_mac 管"转发依据可信 + 外部进不来"，AEAD 管"内容只属于通信双方"，握手层管"身份不可冒充"——成员恶意被限制在"弄脏转发面"，永远够不到内容层。成员以自身身份的正常流量滥用（骚扰/灌数据）由 coordinator 吊销与 ACL 治理，不在帧头设计范围。

### 5.1 预认证最小解析与资源分配后置（REQ-059）

数据面 UDP 入口对**未认证字节**的处理纪律——两条硬规则（ lessons CN-05 / CN-02 的上游约束；REQ-046/REQ-047 限速管"到达速率"，本规则管"解析与分配时机"，互不替代）：

1. **认证前最小解析**：入口认证（route_mac 校验 / AEAD 解密 / 握手验证）通过之前，只允许 **magic / 长度 / 固定头字段级别**的解析——首字节端口分派（CONNECTIVITY §2.1）、34B/42B 定长帧头字段、probe 17B 定长头；**禁止把未认证字节反序列化为富结构**（protobuf/serde 类）。载荷的一切结构化解析（会话消息、握手消息体）都在认证通过之后。解析 fail-closed（非法输入一律丢弃、禁止 panic）是 CN-02 的健壮性基线，本规则额外约束**解析发生的时机**
2. **资源分配后置**：认证失败路径除读缓冲外**零持久分配**——逐包接收缓冲跨包复用（§2.2/§8，REQ-053），逐包零分配；probe 回包受 per-source 限速、在途探测表有硬上限（CONNECTIVITY §4.3）；认证失败不建立任何逐攻击者持久状态（表项/timer/任务）

**fuzz 验收**：预认证解析入口（帧头 decode / open_frame / probe decode / 端口分派）纳入鲁棒性 fuzz 语料——畸形与随机输入不 panic、错误只能经 `Result`/`Option` 返回（SEC-08 闭环）。

## 6. 密钥体系

| 密钥 | 用途 | 持有者 | 生命周期 |
|---|---|---|---|
| Noise 静态密钥对 | Noise_XX 握手身份 | 各节点 | 长期（文件持久化） |
| 会话密钥（ChaCha20-Poly1305） | 载荷加密 + AAD 认证 | 节点对双方 | 握手派生；**Noise rekey 静默轮换**（定时 24h + 控制面事件联动，双密钥窗口 5s 残留期，重放窗口/nonce 随新密钥重置） |
| coordinator 主密钥 | 派生转发密钥（仅存于 coordinator，不下发） | coordinator | 长期，可轮换 |
| 转发密钥 `key_dst` | route_mac 计算 | 目的节点 + 途经的转发节点 | coordinator 逐个下发，可轮换 |

## 7. 设计依据与对比

- **外部组网项目**：明文帧头 + 零认证（AEAD 的 AAD 为空），多跳靠 `forward_counter` 逐跳递减（帧头字段被中间节点修改，因此无法认证）。本设计与其差异：转发节点只改外层地址、不动帧头 → 帧头可完整认证；仅 `ttl` 裸奔（做法 A）达到同样的防环目的（教训见 lessons/frame-security/FS-01）
- **IPsec AH（RFC 4302）**：TTL 逐跳变化字段排除在认证外的先例（本设计进一步把 ttl 置零同时用于 route_mac 与 AAD 输入）
- **QUIC Connection ID / Tailscale DERP 帧头**：明文帧头供中间节点转发的成熟实践

## 9. 控制面接口（见 CONTROL_PLANE.md）

控制面协议完整设计见 [CONTROL_PLANE](./control-plane.md)，需求清单不再内联。数据面依赖的关键交互点：

1. **node_id**：coordinator 唯一分配 4B ID；联邦场景高 8 位 = 网络号（ID 空间分段，CONTROL_PLANE §7.3）
2. **身份绑定**：coordinator 签名 `node_id ⇔ Noise 静态公钥`；握手层双保险——msg1 携带目标 node_id（§2.3）+ 握手后交叉验证（CONTROL_PLANE §3.1/§6），防中继/成员重定向与冒充
3. **key_dst**：coordinator 按 `to_node_id` 派生逐个下发；**broadcast_key 按需下发**（仅能力位含 `broadcast` 的节点，CONTROL_PLANE §3.1/§3.3）；桥节点（联邦 v2）持双方网络密钥（CONTROL_PLANE §3.3）
4. **netmap**：`node_id → 端点/公钥/能力`，带版本号 CAS（CONTROL_PLANE §3.2）
5. **心跳**：周期与租约超时语义由控制面统一定义（CONTROL_PLANE §3.4）
6. **路径服务与路径授权（v1.5/v2，CONTROL_PLANE §3.11）**：v2 帧头新增**固定 8B `path_id`**（34B → 42B），**纳入 route_mac 与 AEAD AAD 输入**；v2 route_mac 改用 `key_path = KDF(主密钥, path_id, path_epoch)`（按路径签发，只发路径参与者）；**v1 兼容**：`path_id = 0` = 默认路径 = 现有 `key_dst` 语义，v1 帧头不变（隐式 path_id=0），v2 查表多一个默认分支平滑过渡；桥节点跨界按路径段用目标网络 `key_path` 重签（§3.1 例外扩展）
