# ts2021 接入设计（TS2021_LEG）

> landscape-rill 的 tailscale 兼容接入：自研客户端 + 自研服务端（headscale 兼容）+ 官方客户端接入 + 官方 tailnet 备份出口。
> 参照源码：`/root/tailscale`（control/controlbase、control/controlhttp、control/ts2021、tailcfg、derp/）。
> 版本：v0.12（2026-09-30 修订：§4 自研服务端落地规格（REQ-068，替换 headscale））｜ 相关需求：REQ-006 / REQ-021 / REQ-033 / REQ-067 / REQ-068

## 1. 目标与范围

- **主用途**：官方客户端（iOS/Android/macOS/tvOS）经自建 ts2021 兼容控制面接入，与 rill ext 节点组网
- **备份出口**：同一套客户端代码，URL 可配，保留接入官方 tailnet（exit node）的能力
- **数据面**：标准 WireGuard（boringtun），官方客户端不认识自研 42B 帧头——手机是"叶子客户端"
- 明确不做：taildrop、tailscale SSH、tailnet lock、ACL 本地执行（v1 只透传）

## 2. 协议四层栈（对照源码）

| 层 | 源码位置 | 自研要点 |
|---|---|---|
| 传输 | `control/controlhttp/` | HTTPS 连接（TLS 证书验证），升级为长连接流 |
| 安全 | `control/controlbase/` | **Noise IK 握手**：客户端发起 `2B 版本 + 1B 类型 + 2B 长度 + 32B 客户端临时公钥(明文) + 48B 机器公钥(加密) + 16B tag`；服务端回 `1B 类型 + 2B 长度 + 32B 服务端临时公钥(明文) + 16B tag` |
| 会话 | `control/ts2021/` | Noise 之上跑 **HTTP/2**（可选 early payload：`\xff\xff\xffTS` + 4B 长度 + JSON EarlyNoise） |
| 消息 | `tailcfg/` | **tailcfg JSON**（RegisterRequest/MapRequest 等 Go 结构体的 JSON 序列化，**非 protobuf**——v0.5 对照 tailscale v1.101.0-pre ts2021 client 更正，历史文档"protobuf 最小子集"有误） |

**关键点**：服务端静态公钥在引导阶段（HTTPS）获取，随后升级为 Noise 会话；HTTP/2 复用现成 h2 库（如 `h2` crate），多路复用所有控制消息。

### 2.1 controlbase 帧与协议常量（v0.4 落地规格，对照 tailscale control/controlbase）

- **Noise 实例**：`Noise_IK_25519_ChaChaPoly_BLAKE2s`；prologue = `Tailscale Control Protocol v{版本号十进制}`（版本绑定进握手哈希；服务端按 initiation 帧头明文版本混入 prologue，版本裁决在会话层做——controlbase 不拒版本，防降级由两侧哈希一致 + 上层版本裁决共同保证）
- **initiation 帧（101B）**：2B 版本(BE) + 1B 类型(0x01) + 2B 长度(96) + 32B 客户端临时公钥(明文) + 48B 机器公钥(密文) + 16B 空 payload tag；**response 帧（51B）**：1B 类型(0x02) + 2B 长度(48) + 32B 服务端临时公钥(明文) + 16B 空 payload tag；**error 帧**：类型 0x03，未认证公共提示；**record 帧**：类型 0x04 + 2B 密文长
- **传输上限**：单帧总长 ≤ 4096B（含帧头），即单帧明文 ≤ 4077B；超长明文发送侧自动分帧；record nonce = 12B（前 4B 零 + 8B BE 计数器从 0 起），由 AEAD 内部维护
- **会话方向**：Split 出 c1（客户→服务）/ c2（服务→客户）；**失步语义**：任一 record 解密失败即连接不可恢复（fail-closed，恒拒后续解密）
- **落地**：crate `rill-ts2021`（controlbase 模块，snow 承载 Noise 握手数学）；frame type/布局/上限与 tailscale v1.102.2 逐字节核对，单测含独立服务端实现对照（防同源编解码偏差互相掩盖）

### 2.2 控制面链路落地规格（v0.5：/key → 升级 → 会话 → 注册）

- **/key 预取**：TLS 上 `GET /key?v=<capver>` → JSON `{"publicKey": "mkey:<hex>"}`（官方 control server 用大写 `PublicKey`，headscale 小写——解析 alias 兼容）；连接复用官方语义：预取与升级各建一条 TLS 连接
- **controlhttp 升级**：`POST /ts2021 HTTP/1.1`，头 `Upgrade: tailscale-control-protocol` + `Connection: upgrade` + `X-Tailscale-Handshake: <base64(101B msg1)>`（v1.101+ 线格式，msg1 在头不在 body）+ `Content-Length: 0`；服务端回 `101` 后同一流转裸 Noise，依次发出 msg2 与 early payload
- **early payload**：5B magic `\xff\xff\xffTS` + 4B BE 长度 + JSON（`nodeKeyChallenge`）；服务端分 3 次 Write = 3 条 record，客户端按明文字节流重组（不依赖 record 边界）
- **会话**：HTTP/2 prior-knowledge（h2 crate）跑在 NoiseStream（AsyncRead/Write 透明封装）上；注册 = `POST /machine/register`，body = `RegisterRequest` JSON（`Version`/`NodeKey`("nodekey:<hex>")/`Auth.AuthKey`/`Hostinfo.Hostname`），响应 `RegisterResponse` JSON（Error 空且 AuthURL 空 = 成功）
- **capver**：客户端发送 tailcfg CurrentCapabilityVersion（v1.101.0-pre = 141），headscale 0.29.3 接受 ≥113；同值用作 controlbase prologue 版本
- **snow nonce 互操作坑（实现级决定）**：snow 默认 resolver 的 ChaChaPoly nonce 为 **LE** 编码（Noise 规范），tailscale Go 实现为 **BE**（WireGuard 风格）——nonce=0 两者相同故握手总成功、首条 record 恰可解，**第二条起解密必败**；transport 层改为 `dangerously_get_raw_split` 取密钥 + chacha20poly1305 显式 BE nonce（tx/rx 独立计数，INVALID_NONCE 拒用，对齐 tailscale conn.go 设计）；snow 仅保留握手与 keygen
- **e2e 证据**：`e2e/ts2021_register/run.sh`（headscale + lrill 探针 + 官方 tailscaled 三容器，双节点同 tailnet 注册，CI `e2e-ts2021.yml`）

## 3. 自研客户端设计

### 3.1 接入流程

```
配置 control URL（自建/官方）+ 信任锚（CA）
  → HTTPS 引导：machine key 注册 + challenge 签名
  → Noise IK 升级（controlbase 帧）
  → HTTP/2 over Noise + early payload
  → RegisterRequest(auth key + node key) → MapRequest 长轮询（netmap 持续推送）
```

### 3.2 身份与认证

- **machine key**：设备长期身份（跨登录稳定）
- **node key**：每次登录生成，可轮换
- **认证**：auth key 预授权（**v1 定稿，REQ-021**）——自研客户端只有 rill ext 节点一种形态（无人值守常驻），无交互登录场景；auth key 由 headscale API 生成（可 tag/过期/回收），运维自动化。官方 app 的交互式登录（网页/凭据）是**服务端职责**，与自研客户端无关（P0 部署时实证）

### 3.3 数据面

- boringtun 对每个需通信的 tailnet peer 建 WireGuard 会话（对端公钥/端点来自 netmap）
- **中继**：v1 走 DERP 中继（协议简单：HTTPS 握手 + 长度前缀帧转发密文）；disco/NAT 打洞 **v2 候选**（v1 定稿，REQ-021——手机↔rill ext 流量量小，DERP 中转延迟可接受；disco 自研成本高、风险大；mesh 接入已有自研打洞，v2 按需评估）
- **subnet router 广播**：rill ext 节点把 **mesh netmap 的 `routes[]` 汇总（前缀公告，CONTROL_PLANE §3.8）+ 自家 LAN** 作为 subnet routes 广播进自建 tailnet——手机直接路由访问 mesh 资源，这是官方客户端接入 mesh 的唯一路径（已确认）；`routes[]` 为控制面数据源，变更经 netmap 推送联动
- **回程（手机 → mesh 双向可达的必要条件）**：rill ext 节点同时把 **tailnet 地址池（100.64/10 等）公告进 mesh**（白名单允许）——rill 节点学到 `tailnet 空间 → rill ext 节点`，节点回包经 mesh 帧到 rill ext 节点 → WG 封装 → 手机（ROUTE_ENGINE §3 回程）
- **作为 exit node**：解包后按本机路由决策（引擎 → tun0 → WAN NAT）
- **使用 exit node**：非本网流量封装发往 exit peer

#### 3.3.1 v1 落地规格（v0.7，e2e 实证：lrill ⇄ 官方 tailscaled 双向 WG ping + exit 转发）

- **netmap 互操作前提（nmcfg 跳过规则）**：MapRequest 必须携带 **DiscoKey**，且经 Lite 更新（Stream=false + OmitPeers=true + Endpoints + NetInfo.PreferredDERP）上报端点与 HomeDERP——tailscaled 对 `DiscoKey.IsZero() && HomeDERP==0 && !IsWireGuardOnly` 的 peer 直接跳过（不建 WG peer、不回握手）；disco 消息本身可不实现（对端 disco 无回应即常驻 DERP 路径）
- **MapResponse 帧**：4B **LE** 长度前缀 + JSON（headscale reservedResponseHeaderSize 语义）；无 Node 的 keepalive 帧跳过；完整 netmap 仅经 Stream=true 长轮询获得
- **DERP 客户端**：**身份 = node key**（tailscaled 同源，非 disco/machine key）；TLS 上 `GET /derp` 升级 → server greeting（8B magic `DERP🔑` + 32B 服务端公钥）→ FrameClientInfo（32B node 公钥明文 + nacl box `nonce24‖tag16‖ct`——crypto_box AEAD 输出即 nacl 布局，无需重排）；数据帧 SendPacket(0x04)/RecvPacket(0x05) = 32B 对端 node key + WG 包；服务端 ping 帧自动回 pong
- **WG 会话驱动**：boringtun（封装同 dn42 腿 tunnel 同构）；发送双路（对端 UDP 端点 + DERP，探针场景双投）；DERP 收发同连接互斥——单所有权任务循环：排空发送队列 → `update_timers` → 1s 超时收包
- **ICMP echo 应答坑**：重算 reply 的 ICMP checksum 前**必须清零原 checksum 字段**——带着请求侧旧有效值求和取反恒为 0x0800（数学性质），内核校验失败**静默丢弃**（对端 ping 显示 100% 丢包，但 tailscale0 抓包可见回包已到达，极具误导性）；单测按内核标准校验（含 checksum 字段在内求和 = 0xFFFF）
- **exit 使用侧（对端官方 exit node 的过滤语义，e2e 实证）**：tailscaled tstun 入向过滤先查 **localNets**（本节点 tailnet 地址 + AdvertiseRoutes 贡献）再匹配规则——0.0.0.0/0 广播经 shrink 处理：剔除本机直连网段与 **RFC1918 等私有段**（`removeFromDefaultRoute`，guest-wifi 语义），仅回添本机各接口 IP；发往这些段的数据包被"destination not allowed"丢弃（且日志按 logNets 抑制，无 Drop 行——只能看 `debug metrics` 的 `tstun_in_from_wg_drop_filter`）。**docker/内网环境测 exit 必须把目标子网经 `--advertise-routes` 显式广播（进 localNets 白名单）+ headscale `approve-routes` 审批**，否则数据面全通也过不了过滤。回程依赖内核转发 + nftables MASQUERADE（`firewallmode=nft-forced` 时无 iptables 链，规则在 nft 表）+ conntrack 反 NAT；对端 AllowedIPs 含 0.0.0.0/0 时**取 peer 目标地址必须过滤 /32 主机路由**（`first_ipv4` 只认 `/32`），否则默认路由 0.0.0.0 被当目标

#### 3.3.2 运行时集成（v0.8，2026-09-30 定稿：runtime 内建会话模块）

探针形态（§3.3.1）升级为 rill-node 内建腿，**与 dn42 腿同构**（后台任务 + 通道接驳，主循环非阻塞泵）：

- **形态**：`Ts2021Leg`（rill-node/src/runtime/ts2021.rs）= 控制面任务（register → `/machine/map` 长轮询流；machine key 持久化、node key 每次启动新生成 = 轮换路径，TSL-10）+ 数据面任务（DERP 驱动循环 + UDP 直连收包，per-peer boringtun 会话，双路发送复用探针实证形态）。Node 侧仅持通道句柄：出站包通道（LAN/mesh → tailnet）、入站明文通道（tailnet → 引擎裁决）、netmap 事件通道
- **路由接线（ROUTE_ENGINE §3）**：netmap peer 的 AllowedIPs（/32 主机 + 已审批子网路由；0.0.0.0/0 等默认路由除外）→ `RouteSource::Tailnet` + `RouteVia::Tailnet(hex node key)` 注入 LPM；peer 消失按 via 全量移除。可达性谓词 = peer 在表（WG 封装本身懒握手，无需预建会话）
- **数据路径**：LAN → tailnet = `pump_lan_packet` Tailnet 臂；mesh → tailnet = transit 扩展（回程）；tailnet → mesh/dn42 = 解包明文 → 引擎裁决出对应腿（subnet router 转发）；tailnet → LAN/WAN = 解包明文 → 写 tun0（内核转发 + MASQUERADE 回程 = exit 被用作）。**transit 图无自环**：tailnet 入站命中 Tailnet 路由 = 丢弃（反射防护）
- **subnet router 广播（TSL-05）**：MapRequest `Hostinfo.RoutableIPs` = mesh `routes[]` 汇总（运行时联动：mesh netmap 变更 → watch 通知 → 重发长轮询携带新 RoutableIPs）+ 自家 LAN/配置静态前缀；headscale 审批后进对端 AllowedIPs
- **exit 被用作（TSL-07）**：同通道广播 `0.0.0.0/0` + `::/0`（配置开关）；对端官方客户端将本节点选为 exit node
- **验证边界**：e2e 全程 docker 内自建 headscale + 官方 tailscaled 对端，不引入官方云/公网 DERP（TSL-02/03/09 等真外部场景维持低频手工 smoke）

**e2e 实证语义（v0.10 补）**：netmap 全量重放（peer 集合不变或部分更新）**必须保留在场 peer 的既有 boringtun 隧道**，仅刷新端点/AllowedIPs、新建消失差集——会话表全量重建会杀活会话，对端 wireguard 按旧 session index 续传、我侧静默丢弃，最长 **REKEY_AFTER（90s）** 才重握手恢复（e2e 表现：peer tx 持续增长、rx 停在握手后水位、断言窗内不收敛；同机制下 mesh 路由广播触发的重发长轮询会让每个 netmap 帧都携带 Peers，重放频率不低）。回归单测 `merge_sessions_preserves_live_session` 锁定该行为

**增量 peer 帧合并（v0.11 补，REQ-067）**：协议上，初始全量 netmap 之后的 peer 变更可以增量帧到达——`PeersChanged`（全条目 upsert，Node 同构）、`PeersRemoved`（数字 node ID 数组）、`PeersChangedPatch`（字段级 patch，仅出现字段替换；Online/PeerSeen/DERP 区域等显式不解析，按条数观测）。解析与合并语义：

- **控制侧快照**（数字 node ID 键控）为合并基线：全量帧重建快照，增量帧在快照上合并后同样走 `Netmap` 事件 + `SetPeers` 下发——merge_sessions 保活语义对全量/增量一致（在场 peer 保留隧道）
- **身份双层**：数字 node ID = 服务端稳定关联键（增量帧定位条目）；hex(node key) = WG 会话身份。**node key 轮换 = 同 nid 整条替换**，下游 merge_sessions 走旧删新建（旧会话拆、新隧道建）
- **增量帧不触发 Lite/DERP**：端点广播节奏维持全量帧路径——对端 online 抖动即产生增量帧，逐帧 Lite 只会放大服务端写放大
- 未携带 nid 的 patch/removed 条目无法关联、跳过（全量 `Peers` 帧总携带 ID，稳态不落此分支）

**e2e 实证服务端语义（headscale 0.29.3，v0.11 补，TSL-11 两轮排障结论）**：

- **无中流推送**：node 增删/断连期间，流式对端零推送（官方 tailscaled 同样收不到，长轮询 ~500s 服务端到期空响应 bytes=0 后重开）——peer 变更经下一轮询的**全量** netmap 传播（官方 tailscaled 同周期行为）。流持有语义不因此失效：online 状态与广播路由仍依赖流在场。增量帧解析/合并保留给会推送的服务端（官方 SaaS / P3 自研服务端），由单测锁定
- **对端重启自身不产生增量帧**：同 key 同端点 = 服务端视角无变更；增量路径的触发是 peer 增删/端点变化，非连接重建

回归单测：解码 `map_response_decodes_incremental_peer_frames`（含缺省 ≠ 空集坍缩）+ 合并 `apply_delta_merges_incremental_frames`（keepalive 判 None / upsert 保身份 / patch 按 nid / removed 清理 / key 轮换迁移）；e2e TSL-11 两段：node-c 重启 → 旧会话经 rekey 重建（ping 恢复不重注册）；临时节点加入/删除 + 强制重轮询（重注册 = 轮询周期的确定性等价物）→ 全量 netmap 反映 peer 2→1

e2e 落地（v0.9，`e2e/ts2021_runtime/`）实证的三条服务端交互语义（TSL-05/TSL-07 排障结论，均 e2e 复现+修复验证）：

- **长轮询流必须持有**：`/machine/map` Stream=true 响应在同一 HTTP 流上持续推送后续 MapResponse 帧；每帧读后重开新流 = headscale 侧节点 online 状态抖动 → 对端 tailscaled 反复 Reconfig 撤订阅户路由。广播变更（poke）才重开流（新 MapRequest 才携带新 Hostinfo）
- **MapResponse 的 `Peers` 缺省 ≠ 空集**：headscale 轻量更新帧（keepalive/无 peer 变更）不带 `Peers` 字段，语义为"不变更"；serde `default` Vec 会把缺省坍缩成空集，netmap 全量替换语义下会误清空会话表（表现：WG 发起重复、对端 tx 增 rx 零）。必须用 `Option<Vec>` 区分
- **每个 MapRequest 的 Hostinfo 都会覆写节点广播路由**：Lite 端点更新（OmitPeers=true）若不带 `RoutableIPs`，headscale 会把已收集的广播路由清空。Lite 更新必须携带与长轮询同构的全量 Hostinfo（tailscaled 同源行为）

## 4. 自建服务端（自研替换 headscale，REQ-068）

### 4.1 路线

1. **P0 过渡**（已完成，实证留档 §6）：开源 headscale + derper
2. **P3 自研**（已落地，v0.12）：`rill-ts2021` 的 `server` 模块 + rilld `ts2021_server` 配置段（`rilld/src/ts2021_run.rs`：TLS accept 循环 + 连接分派）。协议库内客户端/服务端同源共存，防自研两侧编解码同源偏差（headscale 兼容参照改由 `e2e/ts2021_register`、`e2e/p0_tailscale` 场景承担，二进制缓存）

### 4.2 落地规格

- **部署形态**：配置段 `ts2021_server`（network/hostname/listen_addr/tls/noise_key_path/derp_key_path/auth_keys/routes_whitelist/allow_exit），加载即校验 fail-closed；与 mesh coordinator **同进程可共存、协议独立**（ARCHITECTURE §6 浅结合）——纯 ts2021_server 配置（无 coord/node 字段）亦可独立运行。v1 **内存态**（注册表、地址分配）：服务端重启即清空，客户端经重注册自愈（自研客户端重连即重注册；官方 tailscaled 控制面失联同理）。Noise/DERP 私钥 hex 文件持久化（0600，缺省生成——重启稳定，客户端每次 establish 都重取 /key，轮换亦兼容）
- **连接路由**（单 TLS 监听，HTTP/1.1 首请求分流）：`GET /key`（Noise 公钥 JSON，headscale 小写字段名）｜`POST /ts2021`（controlhttp 升级 101 → **msg2 裸写** → early payload → h2 控制面）｜`GET /derp`（DERP 升级 → 内嵌 DERP 会话）。DERPPort = 控制面监听端口（同 TLS 监听复用，headscale 内嵌 DERP 同构）
- **Noise 响应侧**：`ServerHandshake`（snow responder；prologue 按 initiation 帧头明文版本混入；machine = IK 远端静态公钥，握手即机器身份证明）；msg2 是**未加密 Noise 帧，必须裸写**——封进 record 会让客户端帧头解析失步
- **注册语义**：机器身份 = Noise IK 静态公钥（注册幂等键）；节点身份 = node key（同 machine 重注册 = 轮换 node key/hostname，保 nid 与地址；跨机器占用已有 node key → 拒绝）。auth key = **lrk 无状态校验**（解析 + 过期 + 配置集合精确匹配，REQ-043 同构，`lrill authkey --ttl 0` 生成长期 key）
- **netmap 语义**（对齐 §3.3.2 实证形状）：`Stream=true` 长轮询**流持有**（同流推送后续帧；每请求独立任务——Lite 更新与长轮询并发复用连接）+ 初始全量帧；Lite 更新（Stream=false）回 200 空 body；keepalive 60s 周期帧；`Peers` 缺省 ≠ 空集；每 MapRequest 的 Hostinfo **覆写**节点广播路由（白名单过滤后进对端 AllowedIPs 与 PrimaryRoutes）；tailnet 地址 = 100.64.0.N/32 + fd7a:115c:a1e0::N/128 同序号顺序分配
- **增量推送**（REQ-067 的真实生产者，headscale 0.29 无此能力）：注册表变更经 broadcast 事件 → 持有流**同流**推送 `PeersChanged`/`PeersRemoved` 增量帧（空数组省略——Go omitempty 同源；接收者自身条目过滤）；事件滞后（消费太慢）→ 全量帧重发自愈。`PeersChangedPatch` 不实现
- **子网路由审批**：`routes_whitelist`（covered-by 即批，mesh `announce_whitelist` 哲学同构）+ **`allow_exit` 独立开关**（0.0.0.0/0、::/0）——默认路由混入白名单会 covered-by 放行一切，语义不成立，**加载即拒绝**
- **DERP 服务端**：问候（magic `DERP🔑` + 服务端公钥）→ FrameClientInfo（nacl box 持有证明，服务端私钥解）→ 会话表（node key → 出站通道）→ SendPacket→RecvPacket 按 node key 中继 + Ping/Pong 自动应答 + 30s 服务端 ping
- **e2e 注入**（REQ-057 同源哲学）：`RILL_E2E_TS2021_EVICT_NODE=<hostname>` 装填 + `/tmp/rill-e2e-evict` marker 文件触发驱逐（PeersRemoved 增量帧的 e2e 触发器）

### 4.3 线格式实证坑（官方 tailscaled 对照，e2e 排障结论）

| 坑 | 结论 |
|---|---|
| early payload challenge 前缀 | `chalpub:<hex64>`（ChallengePublic 专用前缀，非 `challengekey:`——官方 UnmarshalText 按前缀裁决，错前缀 = register 循环重试） |
| RegisterResponse.Login.ID | Go 侧 `LoginID` **整型**——字符串 `"ID"` 会让官方客户端 JSON 反序列化直接失败；User/Login 两对象必须始终携带（Error 载荷路径同） |
| h2 send_response 的 end_of_stream | 置 true 后流即关闭、`send_data` 落空——客户端拿到空 body（JSON EOF）；单发响应必须 `send_response(.., false)` + `send_data(.., true)` |
| 增量帧空数组 | `PeersRemoved: []` 省略（omitempty 同源）——空数组在客户端 `Option<Vec>` 语义下 ≠ 缺省 |

### 4.4 e2e 实证（自研服务端）

`e2e/ts2021_runtime/`（v0.12 起）：控制面容器 = lrill（ts2021_server 段），**官方 tailscaled（node-c/node-d）+ lrill 双形态客户端同 tailnet 接入自研服务端**——TSL-05 subnet router / TSL-07 exit / TSL-11 增量推送全量回归（headscale 时代的三条服务端交互语义：流持有、Peers 缺省、Hostinfo 覆写——见 §3.3.2，在自研服务端上同构保持）。进程内集成测试（`rill-ts2021/src/server/tests.rs`）：注册准入/幂等、全量 netmap 形状（DERPMap 客户端可解析）、持有流增量帧、Lite 覆写与白名单丢弃、跨机器冒用 401、DERP 双客户端中继、全栈（/key→升级→register→map）

## 6. P0 过渡部署手册（headscale + derper）

> 目标：最快跑通"官方 app 入网"，为后续工作提供端到端验证环境。

1. **部署 headscale**：单机服务（默认 8080），配置 `server_url` 为公网可达地址（HTTPS 必需，可用反代/自签证书——官方客户端要求有效 TLS 证书，建议反代 + Let's Encrypt）
2. **部署 derper**：官方 derper 二进制或容器，暴露 443；在 headscale 配置里注册 DERP 服务器（`derp_map`）
3. **创建用户 + auth key**：`headscale users create <user>`、`headscale nodes register --user <user> --key <preauthkey>`
4. **rill ext 节点接入**：自研 ts2021 客户端（P2）或临时用官方 `tailscale` CLI `--login-server` 验证（P0 阶段可接受）
5. **手机接入**：按 §5 矩阵配置 URL → 登录/输入 auth key → 入网
6. **subnet router 验证**：rill ext 节点启用 `--advertise-routes`（临时验证；自研实现时在用户态栈内完成广播）

### 6.1 P0 容器化验证记录（2026-08-16 实证通过）

`e2e/p0_tailscale/run_p0.sh`：全容器化 P0（headscale 0.29.3 二进制 + tailscale 1.102.2 官方客户端），**官方 tailscaled（与手机 app 同 ts2021 协议栈）经自建 headscale 入网 + WireGuard 直连互通（0% 丢包）**。验证点与踩坑：

| 项 | 结论 |
|---|---|
| ts2021 协议兼容 | 官方客户端 ⇄ 自建 headscale（Noise + HTTP/2 + tailcfg）全链路通 |
| 认证 | preauth key（reusable）入网通；**交互式登录（网页/OAuth）为服务端职责，需真机 UI 实证（挂账）** |
| TLS | 自签 CA 预装客户端系统信任即可（`update-ca-certificates`）——官方客户端无"跳过证书校验"开关 |
| DERP | headscale **内嵌 DERP**（`derp.server.enabled` + `stun_listen_addr` + `automatically_add_embedded_derp_region`）零部署，客户端自动连接 |
| 数据面 | 同网段容器直连 WireGuard（direct）；跨 NAT 场景由内嵌 DERP 兜底（未实测跨 NAT） |

踩坑：①`tailscaled --tun` 参数是**设备名**（`tailscale0`），传 `/dev/net/tun` 路径会 `tstun.New: invalid argument`；②`headscale` CLI 输出带 ANSI 色码，脚本解析需 `sed 's/\x1b\[[0-9;]*m//g'`；③0.29 的 `preauthkeys create --user` 接受**用户 ID**（`users list` 第一列）；④`docker compose` 的 `${TS_AUTHKEY}` 依赖宿主 shell export——脚本内单进程 export 必须覆盖 compose 调用；⑤Docker Hub 不可达时用 GitHub releases（headscale）+ pkgs.tailscale.com（tgz 含 tailscaled/tailscale）自建镜像
