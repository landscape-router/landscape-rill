# dn42 腿设计（DN42_LEG）

> landscape-rill 的 dn42 互联腿：boringtun 隧道管理 + 自研 eBGP-lite + import/export 过滤策略。
> 版本：v0.2（2026-08-15 重建，含 export policy / 身份信任链 / 多边缘出口 / 实现要点）｜ 相关需求：REQ-005 / REQ-015

## 1. dn42 是什么

dn42 是模拟真实互联网的实验网络：参与者用隧道（主流 WireGuard）互联，跑 **eBGP** 交换路由。本质是"无信任 + 强过滤 + 事后断链"的信任模型：

| 互联网 | dn42 |
|---|---|
| RIR 分配 | **registry**（git 仓库，mntner 用 PGP 签名维护）——记录"谁拥有什么"，不是防恶意 |
| 运营商过滤 | **运营商自行过滤**（只接受 registry 登记的 peer 前缀、拒绝超长子网、bogon、AS 环路、max-prefix） |
| 监测追责 | route collector 记录全网公告；断链即全部惩罚 |

**不能确定 peer 无恶意，也不尝试确定**——恶意者的杀伤范围由你的 import policy 圈住。

## 2. 接入架构

```
边缘节点
  ├── dn42 腿（boringtun 隧道管理）：每个 dn42 peer 一条 WireGuard 隧道（用户态，不建网卡）
  ├── eBGP-lite（Rust 自研）：每条隧道上跑 BGP 会话
  └── import policy：registry 白名单 / max-prefix / 环路拒绝 / bogon
        ↓ 学到的路由注入用户态路由引擎（仅本节点持有，不扩散进 mesh）
```

- **仅边缘持有**（已确认）：dn42 路由只存在于连接 dn42 的边缘节点；**多边缘节点出口选择**：边缘节点把 dn42 空间（172.20/14、fd00::/8）作为 `routes[]` **公告进 mesh**（白名单允许，CONTROL_PLANE §3.8）→ 内部节点 LPM 精确命中 + 多网关冗余自动生效（ROUTE_ENGINE §2）——仍是"仅边缘持有"模型（公告主体是边缘节点，BGP 路由不全网同步）
- boringtun 理由：与"单 TUN、无额外网卡"架构一致；明文包直接进用户态栈
- **身份信任链**：BGP 层本身无身份认证，对端身份由 **boringtun WireGuard 隧道静态密钥认证**保证（隧道建立即认证）——BGP 会话无需额外认证；TCP-MD5（RFC 2385）/GTSM 为可选加固（dn42 隧道内通常不需要）

## 3. eBGP-lite 最小集（自研范围）

### 必须

| 能力 | 依据 |
|---|---|
| eBGP 核心（OPEN/KEEPALIVE/UPDATE/NOTIFICATION、TCP:179、AS_PATH/NEXT_HOP/ORIGIN、撤销） | RFC 4271 |
| **4 字节 ASN** | RFC 6793——dn42 全用 4 字节（424242xxxx），缺了无法互联 |
| **MP-BGP IPv6** | RFC 4760（AFI=2/SAFI=1）——dn42 同时跑 v4/v6 |
| 路由刷新 | RFC 2918（软重配） |
| community 透传 | 只携带不解释（dn42 过滤策略常用） |

### 明确砍掉

Route reflector / 联盟 / ADD-PATH / flowspec（单节点互联用不到）；Graceful restart / BFD（可后置）；Large community 解释（透传即可）。

### 实现路线

- 线格式解析复用 `bgpkit-parser`（已支持 BGP-4/MP-BGP/社区属性）
- 自研：FSM（Idle/Connect/Open/Established）、NLRI 处理、best-path 选择（简化版）、路由注入引擎
- 不做完整 BGP（用户已确认）

## 4. import policy（安全性全部来源）

| 策略 | 内容 |
|---|---|
| 前缀白名单 | 只接受 peer 在 registry 登记的分配前缀（可脚本化生成） |
| 超长子网拒绝 | 不接受超过约定长度的 more-specific |
| AS 环路拒绝 | 收到的路由含自身 ASN 即拒（标准 BGP 行为） |
| bogon 过滤 | 拒绝保留/未分配空间 |
| max-prefix | 会话级前缀数上限，防路由表洪泛 |
| （可选）ROA 源验证 | registry 生成 ROA 表，验证公告前缀的起源 ASN |

## 4.1 export policy（导出策略，v1 定稿：stub 优先）

eBGP 的另一半是"宣布什么"，错误导出 = 把不该给别人的路由给出去：

| 角色 | 行为 | 评价 |
|---|---|---|
| **stub（v1 默认）** | 只 announce 自家前缀（registry 分配段），不重公告 peer 学到的路由 | 职责最小、安全面小，推荐 |
| transit（v2） | 重公告学到的路由（需过滤、防环路、承担带宽） | dn42 常见但责任大，留 v2 |

- 导出前过滤：自家前缀经 registry 核验、禁止把私有/保留空间导出
- 是否 announce mesh 空间（mesh 前缀经 dn42 广播）：需 mesh 空间已由 registry 分配段承载（§6 待定项保留）

## 4.2 实现要点

| 项 | 说明 |
|---|---|
| BGP 定时器 | Hold time 默认 90s（协商取小）、Keepalive 30s（Hold/3）、Connect-retry 30s |
| Capability 协商 | RFC 5492——4B ASN、MP-BGP、route refresh 全部走 capability 协商，缺一不可用 |
| 端口 | 默认 TCP 179；dn42 隧道内常用高层端口（非特权），peer 间协商配置 |
| 双栈隧道 | 每 peer 一条 WG 隧道同时承载 v4+v6（tunnel 地址 + allowed IPs 双栈） |
| best-path | v1 简化：单路径（最短 AS path 优先），ECMP 多路径 v2 |
| parser 鲁棒性 | 畸形 UPDATE/NOTIFICATION 不崩会话（bgpkit-parser 处理 + 自研校验） |
| 会话监控 | 会话状态变化（Established↔断开）上报路由引擎，驱动撤销与 fallback |

## 5. 与数据面/控制面的接口

- **隧道生命周期**：dn42 腿管理 boringtun 会话（peer 端点、allowed IPs、密钥轮换）——配置来源：手工配置（v1）或未来的联邦/管理面
- **路由注入**：BGP 学到的前缀注入用户态路由引擎（ROUTE_ENGINE），带 `via = dn42 腿` 标记
- **故障处理**：隧道断 → BGP 会话断 → 路由撤销 → 引擎 fallback 链生效（如经 mesh 边缘出口）

## 6. 待定项

- dn42 起步规模：先连 1~2 个熟悉 peer 跑通，再考虑 route server 对等
- 前缀过滤白名单的生成与更新机制（手动脚本 vs 自动化）
- 是否 announce mesh 空间（mesh 前缀经 dn42 广播，需 registry 段承载；transit 角色 v2）
