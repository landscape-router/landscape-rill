# FS-09 新增传输通道语义旁路

> 场景：数据面协议与认证 ｜ 状态：✅ 已落档（硬规则）｜ 复核时机：设计/新增任何通道或代理方式时

## 问题（现象）

overlay 有多条承载通道（普通 UDP、KCP、QUIC）把流量送往远端节点。新增 KCP/QUIC 通道后与既有通道语义不一致：

- **场景 A（代理配置被旁路）**：同时开启"系统代理透传"+"KCP 通道"。期望：系统代理开启时所有代理流量在 IP 层透明转发（源端口/序列号原样保留）；实际：KCP 模块无视该标志，更早拦截 TCP SYN，改写源端口与序列号。
- **场景 B（源地址被改写）**：节点 B（虚拟 IP x）访问节点 A（虚拟 IP y）的服务。期望服务看到对端 = B；实际开 KCP/QUIC 后服务看到对端 = A 自身（源被改成本机虚拟 IP）。

## 原因

新通道实现未遵守"透传通道"既有承诺（保留源 IP/源端口/序列号），实现了隐式源地址改写（等价 SNAT + 连接级改写），且绕过系统代理配置——多通道语义各自为政。

## 正确行为

- 源地址保留是透传语义的**固定承诺**，不是逐通道可选项
- 新增通道必须统一遵循代理设置；**禁止隐式 SNAT/源地址改写**，需要改源的需求走显式 exit/NAT 语义
- 外层隧道封装地址可变，**内层原始 IP 头必须原样保留**

## 复核触发点

设计/新增任何通道或代理方式时：

1. 新通道是否遵守系统代理设置？
2. 是否保留原始源 IP/源端口/序列号？
3. 是否引入了静默 SNAT 行为？
