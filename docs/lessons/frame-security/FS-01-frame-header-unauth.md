# FS-01 帧头零认证

> 场景：数据面协议与认证 ｜ 状态：✅ 已落档 ｜ 复核时机：设计/新增任何包类型或帧字段时

## 问题（现象）

隧道协议用**明文帧头**承载转发依据（源/目标节点），而载荷认证的 AAD 为空。后果：

- 目标字段可被改写 → 流量被重定向（DoS 级）
- 清除"已加密"标志后可**明文注入接收端** → 无认证包被当合法包处理，源认证完全失效

## 原因

把帧头和载荷分成两个信任域：帧头觉得"反正要转发就不认证"，载荷觉得"有加密就够了"——忽略了**转发依据本身必须可信**。

## 正确行为

- 转发依据（帧头）必须被认证：载荷 AEAD 的 AAD 必须覆盖帧头（除逐跳可变字段外全部）
- 逐跳可变字段（TTL 类）按约定置零参与认证（参考 IPsec AH 做法），转发节点只改外层地址、不动帧头
- 禁止明文/无认证模式，不存在"关闭加密"的开关

## 复核触发点

设计/新增任何包类型或帧字段时：

1. 帧头是否进 AAD/MAC 覆盖范围？
2. 是否存在绕过认证的路径或"关闭加密"选项？
