# FS-05 安全机制作为附加模式导致功能缺陷

> 场景：数据面协议与认证 ｜ 状态：✅ 架构规避 ｜ 复核时机：中继/多跳转发实现时

## 问题（现象）

安全机制以"附加模式"实现，与核心功能冲突：

- 安全模式与**多跳转发不兼容**（超过一定跳数不通）
- 新旧版本互不兼容
- 结果：安全特性长期处于不可用/半可用状态，用户只能在"安全但不可用"和"可用但不安全"之间选

## 原因

把安全做成正交的附加功能而非转发路径的固有属性——安全与转发是两个独立模块，组合时出现未设计、未测试的交叉状态。

## 正确行为

- 安全是**唯一路径**而非附加模式：所有转发路径默认带安全，不存在"安全模式"开关
- 多跳转发与端到端加密解耦：中间节点不触碰载荷，跳数与安全强度无关

## 复核触发点

中继/多跳转发实现时：

1. 转发节点是否零加解密（不解密载荷）？
2. 是否存在"关闭安全"的模式？
