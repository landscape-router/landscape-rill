# AO-07 管理操作时序型越权（检查/执行窗口）

> 场景：管理面与运维 ｜ 状态：需补：P3 管理 API 设计时（原子授权 + 吊销即时生效） ｜ 复核时机：管理 API/多步管理操作实现时

## 问题（现象）

管理操作的授权检查与执行之间存在时间窗，并发下低权者完成高权操作：授权检查通过后角色被降级，后续执行仍以旧结论放行；权限校验读到旧状态而状态变更已在途；令牌已吊销但在途请求继续完成敏感变更。

## 原因

把授权当成**瞬时谓词**而不是状态机步骤：检查点与生效点之间共享状态可变，操作序列未原子化，授权结论被缓存跨操作使用。

## 正确行为

- 授权判定与状态变更必须原子（同一锁/同一状态机事务内完成），检查后状态已变则操作失败重判
- 敏感操作执行时以**当前生效状态**重新校验，不缓存授权结论跨操作使用
- 会话/令牌的权限变更（降级/吊销）即时生效：在途多步操作的中途校验同样拦截

## 复核触发点

实现管理 API/多步管理操作时：

1. 授权检查与状态变更是否原子？
2. 敏感操作是否以执行时状态重新校验？
3. 令牌降级/吊销是否即时拦截在途操作？
4. 同账号并发操作是否串行化？
