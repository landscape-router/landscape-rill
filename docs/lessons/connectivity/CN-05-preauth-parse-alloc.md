# CN-05 认证前富解析与预认证资源分配

> 场景：连通性 ｜ 状态：已补（REQ-059 合并：规则入 FRAME_HEADER §5.1 / CONNECTIVITY §2.1 / CONTROL_PLANE §3.13，fuzz 验收 SEC-08） ｜ 复核时机：数据面/控制面入口、中继实现时

## 问题（现象）

两类同根因缺陷：

- **认证前富解析**：入口对未认证字节先做结构化反序列化（gob/protobuf 类），之后才验证 HMAC——反序列化器的全部攻击面（深嵌套/自引用/超大字段）暴露给任何发包者
- **认证前分配**：未认证连接即建立任务/缓冲/表项，空闲连接不释放 → 未认证者可耗尽资源，殃及已认证流量

## 原因

把"解析健壮性"（不 panic）当成了"解析最小化"（认证前不解析富结构）；把"限速"（到达速率有界）当成了"分配后置"（状态只在认证后建立）——三个维度互不替代。

## 正确行为

- 认证前只允许最小化解析：magic / 长度 / 固定头字段；富结构反序列化必须在 HMAC/握手验证通过之后
- 逐连接/逐会话状态（缓冲、任务、表项、timer）在认证通过后建立；认证失败路径除读缓冲外零持久分配
- 预认证解析入口纳入 fuzz 范围（畸形/随机输入不 panic、内存有界）
- 与限速叠加使用：限速管速率，本规则管解析与分配时机

## 复核触发点

实现预认证入口（帧/probe/中继/控制面连接）时：

1. 认证前是否只解析固定头字段（无结构化反序列化）？
2. 状态分配是否全部发生在认证通过之后？
3. 预认证路径是否进 fuzz 目标？
