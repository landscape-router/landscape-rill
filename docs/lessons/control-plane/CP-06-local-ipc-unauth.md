# CP-06 本地管理接口与状态变更端点无认证

> 场景：控制面与拓扑同步 ｜ 状态：✅ 架构规避 ｜ 复核时机：新增本地管理接口/daemon socket/Web API 时

## 问题（现象）

两类同根因缺陷：

- daemon 的**本地 IPC socket 无认证**：本地任意用户可连上管理 socket，读取敏感信息乃至任意文件（特权进程代读 = 本地提权）
- **状态变更端点无认证**：关停/重置等破坏性操作端点无鉴权，任何能到达端点的调用方一包触发服务下线——泄露型端点被防护时，破坏型端点被遗漏

## 原因

把"本地可达"当成"可信"：unix socket / loopback 的网络边界被等同于授权边界；端点鉴权清单只枚举了"读"而漏了"写"。

## 正确行为

- 本地 IPC 必须有对端身份验证（peercred 类内核凭据或认证握手），socket 权限最小化（0600 + 专用组），不落 world-accessible 路径
- 状态变更端点与只读端点**同等鉴权**；破坏性操作（关停/重置/吊销）默认拒绝匿名调用方
- 不存在默认开启的无认证端点；管理面新增任何监听体（socket/端口）必须先回答"谁有资格连"

## 复核触发点

新增本地管理接口/daemon socket/Web API 时：

1. 对端身份如何验证（peercred / 认证握手）？
2. socket/端口权限是否最小化（0600 / 专用组）？
3. 状态变更与破坏性端点是否与只读端点同等鉴权？
4. 是否存在默认开启的无认证端点？
