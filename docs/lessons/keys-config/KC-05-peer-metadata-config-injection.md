# KC-05 协商元数据写入本地配置未转义

> 场景：密钥与配置管理 ｜ 状态：需补：接入腿配置生成实现时（转义 + 回读验证） ｜ 复核时机：配置生成/元数据落盘实现时

## 问题（现象）

网络下发的协商元数据（对端名称、主机名、FQDN 等）未经清洗直接写入本地生成的配置文件，特殊字符注入目标语法，改变本地程序行为——典型如 SSH config 的 `Match` 行被节点自报主机名注入，用户连往恶意主机；同类手法适用于任何生成式配置（unit 文件、代理 PAC 等）。

## 原因

信任传递断裂：元数据"来自自家控制面"被当成可信，但控制面条目本身可能来自**节点自报字段**；生成器把元数据当代码片段（直接拼接）而非数据（转义后写入）。

## 正确行为

- 凡跨信任边界而来的字符串（节点自报名称/主机名/FQDN/域名）一律视为不可信，写入配置前按目标语法转义或白名单校验（字符集/长度/结构位置）
- 元数据字段的合法字符集在**控制面入口**就收敛（注册时校验），生成端仍不信任（双重防线）
- 生成的配置需**解析回读验证**：写入后按目标语义解析回来比对预期，失败 fail-closed 拒绝应用

## 复核触发点

实现配置生成/元数据落盘时：

1. 字段是否来自节点自报？
2. 写入前是否按目标语法转义/白名单校验？
3. 控制面入口是否已收敛合法字符集？
4. 生成后是否回读验证（fail-closed）？
