# KC-01 非加密哈希充当 KDF

> 场景：密钥与配置管理 ｜ 状态：✅ 已落档 ｜ 复核时机：密钥体系实现时

## 问题（现象）

用**非加密哈希**（如固定密钥的 SipHash 变体）当 KDF 派生密钥——无安全参数、可预测、非为密钥派生设计，密钥体系建立在错误的原语上。

## 原因

把"快"当作"够用"，混淆 MAC/哈希与 KDF 的用途——性能优先牺牲了密钥派生的安全属性。

## 正确行为

- 密钥派生统一走 KDF（HKDF-SHA256 级），**禁止非加密哈希当 KDF**
- 派生 context 明确（info/salt 区分用途）

## 复核触发点

密钥体系/KDF 实现时：

1. 所有密钥派生是否走 HKDF？
2. 是否误用非加密哈希当 KDF？
