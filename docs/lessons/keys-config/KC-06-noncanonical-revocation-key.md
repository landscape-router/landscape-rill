# KC-06 吊销/身份比对的键未规范化

> 场景：密钥与配置管理 ｜ 状态：已补（REQ-058 合并：规则显式入 CONTROL_PLANE §3.5/§3.1，对抗验证 SEC-30） ｜ 复核时机：实现吊销/身份绑定/条目索引时

## 问题（现象）

吊销/黑名单机制以**签名或证书的可变编码字节**作为识别键：攻击者利用签名可塑性改写编码而不改变语义（或简单重编码证书字段），吊销条目失配 → 已吊销身份绕过黑名单继续入网、身份比对被绕过。

## 原因

识别键选在了非规范的编码形式上——语义等价的两种编码解析不出同一个键；"能唯一标识"被当成了"能稳定比对"。

## 正确行为

- 凡参与吊销索引、身份比对、去重的键必须是**规范形式**：语义等价的编码必须解析出同一个键；或以内容摘要（对规范化输入哈希）为键
- 不以签名字节为条目识别键——重签后识别必须稳定（联邦条目交换/重签场景同样适用）
- 身份比对用原始公钥字节/定长 ID；确定性签名算法（如 Ed25519）从源头消除可塑性，但不能替代键规范化规则

## 复核触发点

实现吊销/身份绑定/条目索引时：

1. 吊销与去重的键是 node_id/原始字节等规范形式吗？
2. 有没有任何索引/比对路径以签名或可变编码字节为键？
3. 重签/重编码后条目识别是否稳定？
