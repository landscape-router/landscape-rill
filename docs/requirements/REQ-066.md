# REQ-066 删除 v1 帧头兼容，统一 42B 帧头

> 类型：决策 ｜ 状态：✅ merged ｜ 提出：2026-09-03 ｜ 合并：2026-09-03
> 去向：FRAME_HEADER §2.1 ｜ 验收场景：FRM-12

## 动机

项目未发布，无 v1 对端，v1/v2 双帧头兼容（发送端按对端 `protocol_version` 回退 34B v1 帧）是纯维护负担：编码/解码/relay 转发/密钥选择全链路双分支，golden vectors、e2e 伪造工具、文档随之翻倍。

## 决策摘要

42B 帧头（固定 8B `path_id`）成为**唯一**帧头格式；`version` 重编号 `0x02 → 0x01`（首发格式 = 版本 1，不复用已退役 34B 布局的版本值），收端仅接受 `0x01`；数据/握手/心跳/广播全部统一 42B；`path_id=0` = 默认路径（`key_dst`）语义保留，relay 转发/收帧分支键由 version 改为 `path_id`；Noise prologue 绑定帧头版本字节机制不变（值仍 `0x01`）；控制面 `protocol_version` 协商通道保留（仅路径服务门控，不做帧格式回退）。

## 验收标准

- FRM-12：golden vectors 与 42B 规范逐字节绑定；非法版本字节（0x00/0x02/0xFF）收端拒绝
- 相关教训：FS-05（安全/兼容机制作为附加模式导致功能缺陷——双格式分支即此类复杂度，以单一格式架构规避）
