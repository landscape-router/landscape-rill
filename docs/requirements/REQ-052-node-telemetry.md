# REQ-052 节点遥测上报（心跳搭载）

> 类型：需求 ｜ 状态：📌 proposed ｜ 优先级：P2 ｜ 依赖：— ｜ 提出：2026-09-01

## 动机

coordinator 权威地知道"注册了谁"，但不知道"数据面实际怎么走"：per-peer 收发/丢帧计数只存在于节点侧（LOG-02 丢帧收口），直连可达性确认（probe confirmed）只出现在节点日志。控制面心跳消息当前为空载荷，是零成本的搭载通道。上报使 coord 汇聚全网数据面视图，同时为路径服务（REQ-034 PathMap）预积累可达性矩阵数据源。

## 决策摘要

- **通道**：搭载现有 Heartbeat（10s 周期），不新建连接/消息族；payload 紧凑定长，计数器为区间值（上报即清零，LOG-02 语义）
- **内容**：
  1. per-peer 收发帧数 + 字节数（区间增量）
  2. 丢帧归因计数（BadRouteMac/会话错误/未知 node_id——节点侧计数器现成）
  3. 直连确认对（对端 node_id + 端点 + RTT）——coord 汇聚为全网可达性矩阵（路径服务原料，REQ-034）
  4. RegisterRequest 补 `version` 字段（lrill 构建版本；hostname/os/protocol_version 已有）
- **coord 侧**：聚合为最新快照（只保留最新，不承诺时序存储），经 REQ-051 状态端点展示
- **边界**：
  - 尽力而为：不重传、不确认；coord 视图允许短暂陈旧（与 netmap 一致性无关，不影响控制面行为）
  - 不上报负载内容、路由表全量；tun 状态等扩展字段留待后续按需追加（proto optional 向后兼容）

## 验收标准（草案）

- proto：Heartbeat 扩展字段 + RegisterRequest.version 向后兼容（旧节点空载荷照常工作）
- 节点侧计数器区间语义单测（上报后清零、下次区间不含旧值）
- coord 收到后聚合快照可见（单测）
- e2e：两节点互 ping 后状态端点（REQ-051）per-peer 计数 > 0、直连对非空（展示断言随 REQ-051 一并落地）

## 关联

- 数据源 → 展示：REQ-051（状态端点）
- 可达性矩阵 → REQ-034（路径服务 PathMap，v1.5 消息族落地前的数据积累）
- 计数器语义：LOG-02（周期摘要，REQ-039）
