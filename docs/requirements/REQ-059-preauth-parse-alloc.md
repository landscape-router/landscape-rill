# REQ-059 预认证最小解析与资源分配后置

> 类型：需求 ｜ 状态：✅ merged ｜ 提出：2026-09-02 ｜ 合并：2026-09-02
> 去向：FRAME_HEADER §5.1 / CONNECTIVITY §2.1 / CONTROL_PLANE §3.13 ｜ 验收场景：SEC-08 ｜ lessons：CN-05（本条 lesson 化）、CN-02（解析 panic——本规则为其上游约束）

## 动机

外部同类协议实现的公开缺陷，两类同根因问题：

1. **认证前解析**：中继入口对未认证字节先做富结构反序列化，之后才验证 HMAC——反序列化器的全部攻击面暴露给任何发包者
2. **认证前分配**：未认证连接即分配任务/缓冲/表项，空闲连接不释放 → 未认证资源耗尽 DoS

现有防线只覆盖一半：CN-02 管"解析不 panic"（健壮性），REQ-046/REQ-047 限速管"到达速率"——都不约束**解析时机**（认证前允许解析到什么粒度）与**分配时机**（状态何时建立）。数据面/控制面入口当前实现满足规则，但属隐式安全，升级为显式硬规则并配 fuzz 验收。

## 决策摘要

1. **认证前最小解析**：预认证路径只允许 magic / 长度 / 固定头字段级别的解析；禁止把未认证字节反序列化为富结构，认证（route_mac/AEAD/握手）通过后才允许结构化解析
2. **资源分配后置**：认证失败路径除读缓冲外零持久分配
3. **与限速叠加**：REQ-046/REQ-047 限速管速率，本规则管时机——互不替代
4. **fuzz 验收**：预认证解析入口纳入 fuzz 目标（SEC-08 一并闭环）
