# REQ-059 预认证最小解析与资源分配后置

> 类型：需求 ｜ 状态：📌 proposed ｜ 优先级：P1 ｜ 依赖：— ｜ 提出：2026-09-02

## 动机

外部同类协议实现的公开缺陷，两类同根因问题：

1. **认证前解析**：中继入口对未认证字节先做富结构反序列化，之后才验证 HMAC——反序列化器的全部攻击面暴露给任何发包者
2. **认证前分配**：未认证连接即分配任务/缓冲/表项，空闲连接不释放 → 未认证资源耗尽 DoS

现有防线只覆盖一半：CN-02 管"解析不 panic"（健壮性），REQ-046/REQ-047 限速管"到达速率"——都不约束**解析时机**（认证前允许解析到什么粒度）与**分配时机**（状态何时建立）。数据面/控制面入口当前实现满足规则，但与 REQ-058 同理属隐式安全，需升级为显式硬规则并配 fuzz 验收（SEC-08 挂账待补，是本条的现成载体）。

## 决策摘要（建议默认值）

1. **认证前最小解析**：预认证路径只允许 magic / 长度 / 固定头字段级别的解析；禁止把未认证字节反序列化为富结构（protobuf decode / serde 等），HMAC/握手验证通过后才允许结构化解析
2. **资源分配后置**：逐连接/逐会话状态（缓冲、任务、表项、timer）在认证通过后分配；认证失败路径除读缓冲外零持久分配
3. **与限速叠加**：REQ-046/REQ-047 限速管速率，本规则管时机——互不替代
4. **fuzz 验收**：预认证解析入口纳入 fuzz 目标（SEC-08 一并闭环）

## 验收标准（草案）

- fuzz：数据面/控制面预认证解析入口，畸形与随机输入不 panic、内存有界（SEC-08 闭环）
- e2e：未认证连接洪泛 → 节点内存/任务数有界，已认证流量不受影响
- 回归：direct/relay e2e 全绿；REQ-046/REQ-047 限速场景不回退
