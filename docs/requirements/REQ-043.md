# REQ-043 auth key 内嵌过期时间

> 类型：需求 ｜ 状态：📌 proposed ｜ 优先级：P1 ｜ 依赖：— ｜ 提出：2026-08-31
> 建议默认值：`lrk-<network>-<expiry_unix>-<secret>`；`lrill authkey --ttl <dur>` 生成时内嵌，**默认 TTL 24 小时**（auth key 仅入场令牌，短命是特性——加入后即无用，泄露窗口有界）；`--ttl 0` = 永不过期

## 动机

现格式 `lrk-<network>-<secret>` 无时间信息，过期策略存在 coordinator 配置 `expires_at` 字段——节点/配置加载时无法即时判断 key 是否过期（需等注册被拒），且过期权威与 key 分离（KC-04 静默失效变体）。

## 约束

- 注册校验仍以 coordinator 为准（嵌入时间为 advisory，防篡改改长有效期）
- 格式变更随协议版本允许（未发布，<2.x 直接变更）；已生成 key 作废（README/e2e 重新生成即可）

## 决策方向

- 格式：`lrk-<network>-<expiry_unix>-<secret>`（expiry = 10 位十进制 unix 秒）
- `parse_auth_key` 返回 (network, expires_at, secret)；expiry 非数字/超长 → 解析拒绝
- coordinator 注册：`now > expires_at` → InvalidAuthKey；`AuthKeySpec.expires_at` / `AuthKeyConfig.expires_at` 字段移除（key 自过期 = 单一权威）
- `lrill authkey --network <slug> [--ttl <dur>]`；默认 24 小时，用户可选有效时长
- 节点侧：`lrill run` 配置加载即拒绝已过期 auth key（fail-fast）
- 顺带修复：network 段含 `-` 的隐藏不一致（现格式 split_once 实际不支持，validate_network 收紧为不含连字符）

## 验收标准（草案）

- 解析已过期 key 立即失败（单测）；coordinator 配置含过期 key 拒绝启动；未过期 key 注册不受影响
