# REQ-043 auth key 内嵌过期时间

> 类型：需求 ｜ 状态：✅ merged ｜ 提出：2026-08-31 ｜ 合并：2026-09-01 ｜ 去向：CONTROL_PLANE §6/§3.1/§3.12 ｜ 验收场景：CTL-17 ｜ 修订：REQ-036（key 格式与过期语义）｜ 相关教训：KC-04

## 动机

现格式 `lrk-<network>-<secret>` 无时间信息，过期策略在 coordinator 配置 `expires_at` 字段——解析方无法即时判断过期（KC-04 静默失效变体），过期权威与 key 分离。

## 决策摘要

格式改 `lrk-<network>-<expiry>-<secret>`（expiry = 十进制 unix 秒，`0` = 永不过期），**解析即知过期**。`lrill authkey --ttl <dur>` 生成时内嵌（**默认 24h**，`0` = 永不过期）；过期在**注册时（admission）校验**（嵌入时间仅 advisory，coordinator 是最终裁决，防篡改 key 改长有效期）；`AuthKeyConfig.expires_at` 移除（key 自过期 = 单一权威）。已过期 key 可留在配置（inert，不阻断启动——硬拒绝会卡死已注册节点的挑战恢复）；节点侧对过期 key 启动告警不阻断。network 段收紧为不含连字符（段分隔符冲突）。

## 验收标准

- 解析已过期 key 立即失败（parse 层单测）；注册时过期 key 被拒；未过期 key 注册不受影响；节点启动对过期 key 告警不阻断（挑战恢复路径可用）
