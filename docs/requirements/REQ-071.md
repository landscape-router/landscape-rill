# REQ-071 mesh 出口（默认路由 exit）

> 类型：需求 ｜ 状态：✅ merged ｜ 提出：2026-10-02 ｜ 合并：2026-10-02
> 去向：ROUTE_ENGINE §5.1 / §4 / CONTROL_PLANE §3.3/§3.12 ｜ 验收场景：RTE-06（单元 + e2e）/ E2E-05（exit_wan） ｜ lessons：—

## 动机

ROUTE_ENGINE §5 定义了 mesh exit 语义（`/0` 不入前缀公告，走 exit 透传）但未落地：E2E-05（rill 节点 → 互联网）长期挂起，§8 未决项"mesh exit 与 ts2021 exit 的默认路由竞争优先级"无解。设计方向（用户裁定）：**不取最小实现，取最正确且维护方便的机制**——项目未发布，允许破坏性变更。

## 决策摘要

1. **能力位 + 协调者准入**（与 relay roster 同族，而非复用 whitelist-0/0 前缀公告）：`能力位 exit(0x08)（注册声明）∧ 网络 exits.allow 授权集` → netmap `exit` 标记——能力位只是必要条件，授权 fail-closed（缺省/空 = 全拒）；生效集（能力位 ∩ allow）变化才 bump netmap（纯 allow 增删无能力位对端不扰动）
2. **能力位常量统一家**：`rill-core/src/control/capability.rs` 持有 relay/exit/broadcast/acl 四常量（core/coord 两处散落合并；exit = 0x08，CONTROL_PLANE §3.1 能力位表原定，0x02 为 bridge 预留不得占用）
3. **DefaultRouteResolver**（`rill-core/src/route/default.rs`，I/O-free）：LPM miss → 按节点静态偏好序 `default_route_preference: ["tailnet","mesh"]`（默认空 = 不启用，行为不变；重复项拒绝）取首个可达候选；WAN 隐式链末位（不可配置）；**无环不变量：self_exit 跳过 mesh 来源**（exit 不给 exit 转发默认流量）
4. **候选喂入**：mesh 侧随 netmap 原子更新（exit ∧ 在线 ∧ ≠self，离线即出集）；tailnet 侧 = ts2021 netmap 中 allowed_ips 含 /0 的 peer（闭环 ts2021.rs 旧 TODO"/0 不进 LPM"）
5. **出口节点转发 = 内核转发**：出口节点解帧写 land0 → 内核 ip_forward → WAN 口（显式回程路由或上游 NAT；不引入用户态 NAT/回话机制）

## 去向

- **ROUTE_ENGINE §5.1**：默认路由解析（候选来源/偏好序/无环不变量/准入链）
- **ROUTE_ENGINE §4**：默认路由 fallback 链示例更新（偏好序 + WAN 隐式链末）
- **CONTROL_PLANE §3.3**：netmap 条目 `exit` 标记（wire 字段 12）
- **CONTROL_PLANE §3.12**：`networks[].exits { allow[] }` 准入段（授权集语义，SIGHUP 热更新）
- 验收：RTE-06 单元（解析器 4 例 + coord 准入 3 例）；E2E-05（`e2e/scenarios/exit_wan.sh`：fail-closed 基线 → SIGHUP 运行时授权双栈借道 → 出口停机租约过期回退丢弃）

## 教训

- docker v4-only 网络对接口逐个写 `disable_ipv6=1`（compose 的 all/default sysctl 管不到，privileged 容器 proc 写入亦不可靠）——双栈 e2e 的第二网络直接用 `enable_ipv6` + v6 ipam（docker 原生启用，零注入）
- 出口使用方的内核 inet 前缀路由必须指向 land0：否则宿主（持有 docker 网段路由）默认路由直达 inet 网，绕过 mesh 使断言失真
