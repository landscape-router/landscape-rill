# REQ-063 多路并发双发（双信封复制）

> 类型：需求 ｜ 状态：📌 proposed ｜ 优先级：P5 ｜ 依赖：REQ-034 ｜ 提出：2026-09-02

## 动机

会话与路径天然解耦：session 是 E2E 的（seq + AEAD 按目的键控），路径只是外层信封——同一 payload+seq 可封两个信封（path_id=0 默认帧 + path_id≠0 路径帧）。接收侧会话层 ReplayWindow（1024-seq 滑窗位图，`check_and_mark`）已按 seq 去重，重复信封免费丢弃；同明文同 seq 重发 = 相同密文，不构成 nonce 滥用。现有可用性缺口：Noise_XX 握手期（3-RTT）丢包代价高（等超时重传）；miss 检测到 failover 完成之间的窗口纯丢包。

## 决策摘要（建议默认值）

1. **双信封并发**：同 payload+seq 构造两个信封（默认路径 + 显式路径，或两条显式路径）并发发出；接收侧首个到达正常解密交付、后续按 Replay 丢弃（现有机制，零新增）
2. **场景三限（= 带宽礼貌的答案，双发只发生在有界窗口，非常驻）**：
   - **握手帧双发**：Noise_XX 3-RTT 期间（包少成本小，乱序无感）
   - **降质窗口双发**：miss 检测触发进入，failover 完成或健康恢复退出（填上切换 gap，现状该窗口纯丢包）
   - **标记流双发**：配置标记的流（标记方式见开放问题）
3. **乱序对策 = 场景规避，非机制解决**（窄窗口乱序交付严格优于现状丢包；内层 TCP dupACK 降吞吐但不坏）
4. **预算旋钮**：每流字节预算 / 降质窗口时长上限（防双发无限持续；默认数值见开放问题）
5. **msg1 幂等守卫**：重复 msg1 现会重建 responder 并重发 msg2（`handle_msg1` 无幂等守卫）——加幂等处理

## 非目标

- 包粒度分流（per-packet spraying——乱序无通用解，需重排缓冲，届时独立立项）
- 通用重排缓冲（seq 键控 + 超时冲刷——仅包粒度多路需要，MPTCP 级工程）
- 全量常驻双发（带宽 ×2，relay 为自愿节点）
- FEC（前向纠错——将来作为双发的带宽高效替代评估）

## 开放问题（立项评审拍板）

1. 预算旋钮默认值（字节预算 / 窗口时长）
2. 标记流的标记方式（配置 per-prefix vs 内层 DSCP 位）
3. 双发触发的健康阈值与 miss 机器的联动参数

## 验收标准（草案）

- 去重断言：双信封同 seq 只交付一次（第二信封按 Replay 丢弃，单测）
- 乱序边界断言：快路超前慢路 < 1024 seq 时全送达；超出时迟到帧按 Replay 丢弃（退化为快路单发质量，不劣于现状，单测构造延迟差）
- 降质窗口进入/退出触发单测（miss 阈值进入、恢复/failover 完成退出、预算耗尽退出）
- msg1 幂等单测（重复 msg1 不重建 responder 状态污染）
- e2e：主路径丢包场景下切换无感（应用层吞吐不归零）
